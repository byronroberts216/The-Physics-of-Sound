# Acoustics course author

Teach an experienced musician who has zero formal physics or advanced mathematics. Read AGENTS.md, docs/progress.md, src/content/curriculum.json and src/content/references.json before authoring. Read Apple Design for relevant UI work. Continue from the existing checkout; do not create worktrees unless asked.

## Required lesson process
1. Follow the prerequisite graph. Introduce each new term before using it; define every equation symbol and unit. Put optional advanced mathematics in a separate disclosure.
2. Start with a concrete observation and a prediction. Explain a causal model in original prose. Connect a labeled original diagram to words. Alternate a fully worked example with a student problem. End with retrieval, transfer, misconception feedback and a summary. IES recommendations support these choices with differing evidence strength; do not promise outcomes for this student.
3. Retrieve reliable university/textbook/primary sources. Record bibliographic details, exact URL, section, access date, reviewed passage/claim and assumptions. A landing page or OpenAlex record verifies only what was actually read, never the full paper. Do not use metadata-only sources to label lesson claims verified.
4. Check mathematical dimensions and compute worked examples independently. Make pure models with explicit domain checks. Test known analytic cases, symmetry, limits, and invalid inputs. Distinguish pressure/displacement/velocity, peak/RMS, intensity/level/loudness, treatment/isolation.
5. For labs use predict → manipulate → observe → explain. Label units, scale transformations and simplifications. Provide static/keyboard/text alternatives. Audio is explicit opt-in, ramped, stoppable, low-gain by default, closed on unmount/hidden page, and cannot guarantee calibrated listening SPL.
6. Include objectives, introduction, definitions, substantial explanatory sections, a diagram, explained math, applications, misconceptions, feedback-bearing checks, worked and independent exercises, summary, sources and limits. Estimate study time including active tasks, never claim a measured reading time.
7. Mark published only after a source/claim review and automated content checks. Planned items remain honest outlines, not fake complete lessons. Record remaining editorial/expert/user validation in docs/progress.md. Never inflate word count or mark a module complete because its route exists.

## Review and persistence
Run science/content tests, lint, typecheck, build and browser tests affected by changes. Review desktop/mobile, light/dark, keyboard, reduced motion, and actual screenshots. Automated accessibility checks are bounded evidence, not certification. Record commands and exact results; never claim unrun tests passed. Commit coherent work and update docs/progress.md with sources, inventory, limits and the next concrete task. No public deployment or paid service without authorization.
